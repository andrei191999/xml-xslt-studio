## 1. Helger WSDL — SOAP Operation and Element Structure

### Source

- Primary WSDL: `https://peppol.helger.com/wsdvs?wsdl`
- Type definitions (imported): `https://peppol.helger.com/wsdvs?wsdl=1`
- Namespace: `http://peppol.helger.com/ws/documentvalidationservice/201701/`
- WSDL generated by: `XML-WS Runtime 4.0.3` (metro-jax-ws)

### SOAP Operation Name

```
validate
```

SOAPAction value: `"validate"` (with quotes in the header).

### Request Element

Element name in SOAP body: `validateRequestInput`

```xml
<xs:complexType name="RequestType">
  <xs:sequence>
    <xs:element name="XML" type="xs:string"/>
    <!-- The document XML to validate, as escaped text content — NOT child XML -->
  </xs:sequence>
  <xs:attribute name="VESID"          type="xs:string" use="required"/>
  <xs:attribute name="displayLocale"  type="xs:string" default="en" use="optional"/>
</xs:complexType>
<xs:element name="validateRequestInput" type="tns:RequestType"/>
```

### Response Element

Element name in SOAP body: `validateResponseOutput`

```xml
<xs:complexType name="ResponseType">
  <xs:sequence>
    <xs:element name="Result" type="tns:ValidationResultType" minOccurs="0" maxOccurs="unbounded"/>
  </xs:sequence>
  <xs:attribute name="success"              type="xs:boolean"          use="required"/>
  <xs:attribute name="interrupted"          type="xs:boolean"          use="required"/>
  <xs:attribute name="mostSevereErrorLevel" type="tns:ErrorLevelType"  use="optional"/>
  <!-- ErrorLevelType: "SUCCESS" | "WARN" | "ERROR" -->
</xs:complexType>
```

### Result Element (per validation layer)

```xml
<xs:complexType name="ValidationResultType">
  <xs:sequence>
    <xs:element name="Item" type="tns:ItemType" minOccurs="0" maxOccurs="unbounded"/>
  </xs:sequence>
  <xs:attribute name="success"      type="tns:TriStateType" use="required"/>
  <!-- TriStateType: "true" | "false" | "undefined" -->
  <xs:attribute name="artifactType" type="xs:string"        use="required"/>
  <!-- e.g. "xsd", "schematron-xslt" -->
  <xs:attribute name="artifactPath" type="xs:string"        use="required"/>
</xs:complexType>
```

### Item Element (per error/warning)

```xml
<xs:complexType name="ItemType">
  <xs:sequence>
    <xs:element name="Exception" type="xs:string"/>
    <!-- Only present if an internal exception occurred -->
  </xs:sequence>
  <xs:attribute name="errorLevel"     type="tns:ErrorLevelType" use="required"/>
  <!-- "SUCCESS" | "WARN" | "ERROR" -->
  <xs:attribute name="errorID"        type="xs:string"          use="optional"/>
  <xs:attribute name="errorFieldName" type="xs:string"          use="optional"/>
  <xs:attribute name="errorLocation"  type="xs:string"          use="optional"/>
  <xs:attribute name="errorText"      type="xs:string"          use="required"/>
  <xs:attribute name="test"           type="xs:string"          use="optional"/>
</xs:complexType>
```

### Fault Element

```xml
<xs:element name="validateErrorFault" type="xs:string"/>
```

Plain string inside a standard SOAP Fault — e.g. `"Syntactically invalid VESID 'x' provided!"`.

### Namespace Prefixes

| Prefix | URI |
|--------|-----|
| `S` (or `soapenv`) | `http://schemas.xmlsoap.org/soap/envelope/` |
| (default on body elements) | `http://peppol.helger.com/ws/documentvalidationservice/201701/` |

Service matches by namespace URI — any prefix is acceptable on the client side.

### Service Endpoint

```
https://peppol.helger.com/wsdvs
```

### Confirmed Request Template (for helgerValidator.ts)

```xml
<?xml version="1.0" encoding="UTF-8"?>
<soapenv:Envelope
    xmlns:soapenv="http://schemas.xmlsoap.org/soap/envelope/"
    xmlns:ns="http://peppol.helger.com/ws/documentvalidationservice/201701/">
  <soapenv:Header/>
  <soapenv:Body>
    <ns:validateRequestInput VESID="{vesid}" displayLocale="en">
      <ns:XML>{xml_content_xml_escaped}</ns:XML>
    </ns:validateRequestInput>
  </soapenv:Body>
</soapenv:Envelope>
```

Key: document XML is **escaped text** inside `<ns:XML>`, not child XML.

### Live Test Response (HTTP 200)

```xml
<S:Envelope xmlns:S="http://schemas.xmlsoap.org/soap/envelope/">
  <S:Body>
    <validateResponseOutput
        xmlns="http://peppol.helger.com/ws/documentvalidationservice/201701/"
        success="false" interrupted="false" mostSevereErrorLevel="ERROR">

      <Result success="true" artifactType="xsd"
              artifactPath="external/schemas/ubl21/maindoc/UBL-Invoice-2.1.xsd"/>

      <Result success="false" artifactType="schematron-xslt"
              artifactPath="external/schematron/openpeppol/2025.11/xslt/CEN-EN16931-UBL.xslt">
        <Item errorLevel="ERROR" errorID="BR-S-02"
              errorFieldName="/:Invoice[1]"
              errorLocation="uploaded-file"
              errorText="[BR-S-02]-An Invoice that contains an Invoice line (BG-25)..."
              test="(exists(//cac:ClassifiedTaxCategory...))"/>
        <Item errorLevel="WARN" errorID="UBL-CR-429"
              errorFieldName="/:Invoice[1]"
              errorLocation="uploaded-file"
              errorText="[UBL-CR-429]-A UBL invoice should not include..."
              test="not(cac:PaymentMeans/cac:PayeeFinancialAccount/...)"/>
      </Result>

      <Result success="false" artifactType="schematron-xslt"
              artifactPath="external/schematron/openpeppol/2025.11/xslt/PEPPOL-EN16931-UBL.xslt">
        <Item errorLevel="ERROR" errorID="DE-R-016"
              errorFieldName="/:Invoice[1]"
              errorLocation="uploaded-file"
              errorText="If one of the VAT codes S, Z, E, AE, K, G, L, or M is used..."
              test="(not(($BT-95-UBL-Inv = $supportedVATCodes...)))"/>
      </Result>
    </validateResponseOutput>
  </S:Body>
</S:Envelope>
```

**Key observations:**
- Errors/warnings are **attributes on `<Item>`**, not child elements.
- `errorText` contains the human-readable message including rule ID prefix (e.g. `[BR-S-02]-...`).
- `errorID` contains just the rule code (e.g. `BR-S-02`).
- `errorLocation` is always `"uploaded-file"` for inline-validated content.
- `errorFieldName` contains the XPath of the offending node.
- `test` contains the Schematron assertion expression.
- Multiple `<Result>` elements — one per validation layer (XSD, then each Schematron).
- Fault (HTTP 500 for bad VESID) returns a standard SOAP Fault with `<validateErrorFault>` as a plain string.

## 4. VS Code QuickPickItemKind.Separator — Filter Behavior

> **⚠ Correction C3** — The `onDidChangeValue` rebuild in task 2.7 is not needed. VS Code handles this automatically.

### Confirmed Behavior

Source: `src/vs/platform/quickinput/browser/quickInputList.ts` (microsoft/vscode, `filter()` method).

Algorithm when user types a filter query:
1. All separators are initially hidden (`element.hidden = true`).
2. Code walks items in order. For each non-hidden (matching) item, if a separator immediately precedes it, that separator is re-shown.
3. If a separator has **no visible items after it** before the next separator, it stays hidden. Orphaned separators are never shown.

**VS Code auto-hides orphaned separators.** The extension does not need to manually rebuild `qp.items` on each keystroke for separator management.

**Caveat:** When `quickPick.sortByLabel = true`, separators are not rendered at all during filtering. Keep `sortByLabel` at its default (`false`) to preserve separators.

### Simplified task 2.7 guidance

- Do NOT implement the `onDidChangeValue` items-rebuild for separator hiding.
- The `activeItems` pre-selection fix (set after assigning `qp.items`) and the `picked: true` caveat still apply.

## 8. Saxon HE 10.9 JAR — Presence and Trace Format

> **Status: COMPLETE** — JAR copied and trace format empirically verified (Phase 1).

`C:\Workspace\Scripts\lib\saxon-he-10.9.jar` — **now present** (5.5 MB).

### ⚠ Critical Correction — Trace format is XML to stderr, NOT text to a file

The **provisional format in design.md is wrong**. Empirical test with Saxon HE 10.9:

```
java -jar C:\Workspace\Scripts\lib\saxon-he-10.9.jar \
  -s:test.xml -xsl:test.xsl -T
```

**Findings:**
1. **Trace goes to stderr** — stdout contains the clean transform output only.
2. **`-traceout` does NOT create a separate file** — the trace always goes to stderr regardless of this flag.
3. **Format is XML** — wrapped in `<trace saxon-version="10.9" ...>` element (not the simple text format).

### Actual trace format (stderr, verified with Saxon HE 10.9)

```xml
<trace saxon-version="10.9" xmlns:xsl="http://www.w3.org/1999/XSL/Transform">
 <source node="/root" line="2" file="test_trace.xml">
  <xsl:template match="/root" line="4" column="31" module="test_trace.xsl">
   <xsl:apply-templates line="5" column="4" module="test_trace.xsl">
    <source node="/root/item[1]" line="2" file="test_trace.xml">
     <xsl:template match="item" line="7" column="30" module="test_trace.xsl">
      <xsl:value-of line="8" column="1" module="test_trace.xsl">
      </xsl:value-of>
     </xsl:template>
    </source><!-- /root/item[1] -->
   </xsl:apply-templates>
  </xsl:template>
 </source><!-- /root -->
</trace>
```

With `-s:-` (stdin): same format, but `file=""` (empty) for source nodes.

### Implementation guidance for Agent F (task 3.8–3.9)

- **Do NOT** use `-traceout` flag — it does nothing.
- **DO** capture **stderr** from the Saxon process to get the trace XML.
- **DO** capture **stdout** for the clean transform output.
- The `parseSaxonTrace` function signature should accept a `traceXml: string` (stderr content), NOT a file path.
- Parse `<xsl:template>` elements' `line` and `module` attributes for XSLT source locations.
- The trace is hierarchical (execution tree), not a flat line-by-line output mapping.
  - Flatten to an ordered list of `{ xsltLine, xsltModule }` entries.
  - Map output line N → nearest preceding template entry (approximation, sufficient for navigation).

### Revised `parseSaxonTrace` signature (corrects task 3.9)

```typescript
// NOT: parseSaxonTrace(traceFilePath: string): Map<number, vscode.Location>
// CORRECT:
parseSaxonTrace(traceXml: string, xsltAbsPath: string): Map<number, vscode.Location>
```

Where `xsltAbsPath` is used to build the `vscode.Uri` for related information links.

Return an empty Map on parse error or empty input — never throw.

### Revised `javaRunner.ts` trace integration (task 2.5)

The `runSaxonTransform` function with tracing should:
- Return `{ stdout: string, traceXml: string }` where `stdout` is the transform output and `traceXml` is the stderr trace.
- NOT write to a temp file for the trace.

## 9. Java Process Kill Behavior on Windows

### Environment Tested

- Node.js: v22.16.0 / Windows 11 / OpenJDK 25.0.2 (Temurin)

### Results

| Scenario | `child.kill()` terminates JVM? | Orphan risk? |
|---|---|---|
| `spawn('java', args, { shell: false })` | **Yes, immediately** | None |
| `spawn('java', args, { shell: true })` | Kills shell only — JVM **survives** | **High** |

- `child.kill()` on Windows calls `TerminateProcess(handle)` — the JVM is gone within one event loop tick.
- `SIGTERM` and `SIGKILL` are functionally identical on Windows — both call `TerminateProcess`.
- With `shell: false`, plain `child.kill()` is sufficient and reliable.
- With `shell: true`, the JVM becomes an orphan process (confirmed live).

### Recommendation for javaRunner.ts

Always use `spawn('java', argsArray, { shell: false })`. Do NOT use a command string with `shell: true`. The `tree-kill` package is not needed.
